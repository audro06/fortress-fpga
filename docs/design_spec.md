# 포트리스 설계 사양

- 기준: 11-03 웹 시뮬레이터 설계 + **11-10 제안서 수치** (파워 1~8, 체력 50 / DIP6 ON이면 100)
- 시뮬레이터: https://claude.ai/artifact/FjrCj6MJnH1xUdcv3n9Ped
- RTL 구조와 모듈별 역할은 [rtl_architecture.md](rtl_architecture.md) 참고

## 1. 게임 흐름
- 첫 턴: 두 플레이어 모두 이동만 해요 (P1 → P2). DIP5(발사 후 이동)를 끄면 첫 턴 이동도 없어요.
- 이후 턴: 조준(각도 30~90°) → 파워 충전(1~8 왕복 게이지) → 발사 → 결과 → 이동(제한 없음, 5로 종료)
- 숨김: 내 차례엔 상대 탱크가 안 보이고, 마지막으로 본 자리에 `?`만 떠요. 누군가 발사하는 순간 서로 위치가 드러나요. CPU도 마지막으로 본 위치만 알아요.
- 화면: LCD는 전장 화면 하나예요. 아랫줄은 땅(탱크·벽), 윗줄은 차례인 쪽 HUD예요.
- 바람: 기본은 없어요. 돌풍 이벤트 때만 불어요.
- 승패: 한쪽 체력이 0이면 끝. LCD 깜빡임 + 승리 멜로디. 둘 다 0이면 무승부.

## 2. 맵
- 16칸 중 P1 0~5칸, P2 10~15칸을 쓰고, 탱크는 몸통+대포 2칸이에요.
- 가운데 벽은 7·8칸이에요. 판마다 낮은 벽 2개이거나 한쪽이 2층 탑이에요 (DIP8 OFF면 벽 없음).
- 벽은 온전 → 금 감 → 잔해 → 무너짐 순서로 부서지고, 아래가 무너지면 윗 블록이 떨어져요.

## 3. 포탄 (무제한, 같은 키를 다시 누르면 일반)
| 키 | 포탄 | 피해 (직격/근접/스침) | 특징 |
|---|---|---|---|
| - | 일반 | 35 / 20 / 10 | 근접 4px, 스침 8px |
| 1 | 두 발 | 20 / 12 / 6 | 두 발 연속, 둘째는 파워 ±1 |
| 3 | 넓은 폭탄 | 22 / 16 / 8 | 근접 7px, 스침 13px |
| 7 | 얼음 | 피해 없음 | 탄착 칸 ±1 안의 탱크가 다음 이동 차례에 못 움직임 |
| 9 | 불 | 30 / 15 / 0 | 명중하면 자기 +15, 빗나가면 자기 -15 |

DIP1(특수 포탄)을 끄면 일반만 쓸 수 있어요. 1자리 7세그에 지금 고른 포탄 번호(0~4)가 떠요.

## 4. 3턴마다 이벤트 (2턴 유지, 스텝모터 룰렛으로 선택) - DIP4
- LAVA: 양 진영에 용암 칸이 하나씩 생겨서 그 칸으로 이동할 수 없어요.
- LOW-G: 중력 18 → 11
- GUST: 바람 ±3~5
- QUAKE: 탱크 ±1칸 밀림 + 벽 한 단계 (1턴만)
- FOG: 비행 중인 포탄이 안 보여요.
- METEOR: `!`로 표시한 3칸에 이벤트가 끝날 때 유성이 떨어져요 (20/20/10).

룰렛 원판에는 원점 센서 자리부터 같은 방향으로 60°마다 LAVA, LOW-G, GUST, QUAKE, FOG, METEOR 순서로 붙여요.

## 5. 탄도 (시뮬레이터와 비트 단위로 같음)
- 단위는 1/256 픽셀 정수. 매 프레임 틱(30 Hz)마다 `vx += wind; vh -= grav; x += vx; h += vh`
- 화면 좌표: `px = x >>> 8`, `py = 15 - (h >>> 9)`
- 판정 순서: 맵 밖(px < -4 또는 > 84) → 벽 → 탱크 직격(py ≥ 11, 발사 후 8틱 동안 자기 탱크 제외) → 땅(h ≤ 0)
- 시작값: 속도 ROM `(각도-30)*16 + (ROM파워-1)` → {vx, vh}, 포구 ROM `각도-30` → {x 오프셋, h0}
- **파워 매핑 (제안서 8단계)**: 게임 파워 p(1~8) → ROM 파워 2p (2, 4, ..., 16). 속도 ROM은 16단계 그대로 둬요.
- `sim/tb_trajectory.v`: Python 비트 모델로 만든 정답 104개와 비교하는 테스트벤치 (`tools/gen_roms.py`가 생성)

## 6. LCD CGRAM 슬롯 (용도 고정)
| 슬롯 | 게임 화면 | 타이틀 |
|---|---|---|
| 0 / 1 | P1 몸통 / P1 대포(각도별, cannon_rom) | 같음 |
| 2 / 3 | P2 몸통 / P2 대포(비트 반전) | 같음 |
| 4 | 금 간 벽 | 두 발 아이콘 (게임 끝 화면: 트로피) |
| 5 | 잔해 | 넓은 폭탄 아이콘 |
| 6 | 용암 | 얼음 아이콘 |
| 7 | 포탄 / 폭발(6프레임) / 유성 | 불 아이콘 |

- 내장 문자로 슬롯을 아껴요: 온전한 벽 8'hFF, 궤적 8'hA5, 화면 위 `^`, 지난 탄착 `.`, 숨은 상대 `?`, 유성 경고 `!`, 넓은 폭발 양옆 `*`
- 흔들림은 표시 이동 명령(8'h18/8'h1C), 승리 깜빡임은 표시 ON/OFF(8'h08/8'h0C)

## 7. 장치 매핑
| 장치 | 역할 |
|---|---|
| 3×4 키패드 | 1 두발, 3 넓은, 7 얼음, 9 불 / 2 각도▲, 8 각도▼ / 4 ◀이동, 6 이동▶ / 5 누르면 충전·떼면 발사 / # 처음으로 |
| DIP | 1 특수 포탄 / 2 P2=CPU / 3 CPU 고수 / 4 3턴 이벤트 / 5 발사 후 이동 / 6 체력 100 / 7 효과음·모터 (OFF면 Piezo·서보·스텝모터 모두 꺼짐) / 8 가운데 벽 |
| Text LCD | 전장 화면 (위 6절) |
| 8자리 7세그 | P1 HP │ 다음 이벤트까지 남은 턴 또는 E1~E6 │ P2 HP (타이틀: PLAy) |
| 1자리 7세그 | 고른 포탄 번호 0~4 |
| LED 8개 | 파워 게이지 (파워 p → LED p개) |
| Full color LED 4개 | 차례 색(P1 빨강, P2 파랑), 발사·피격·얼음·이벤트 때 번쩍임, 타이틀 무지개 |
| 서보 | 현재 플레이어 포신 각도 (P2는 180-각도) |
| 스텝모터 + 원점 센서 | 이벤트 룰렛. 전원·리셋 때 원점 찾기 |
| Piezo | 충전음(파워 따라 음 높이), 발사·폭발·명중·얼음·승리 등 효과음 (DIP7) |

DIP 설정은 게임을 시작할 때(5를 누를 때) 읽어서 그 판 동안 고정돼요. 효과음·모터(DIP7)만 언제든 바로 바뀌어요. DIP7을 끄면 룰렛은 돌지 않고 이벤트만 정해져요.

## 8. 시뮬레이터와 다른 점
- 파워 1~8, 체력 50/100 (제안서 기준)
- 룰렛: 스텝모터가 다 돌고 멈춘 뒤에 이벤트를 적용해요 (최소 70틱).
- 유성 3개는 40틱 간격으로 하나씩 떨어져요 (시뮬레이터와 같은 간격, 하드웨어는 포탄 계산기가 하나라 겹치지 않게).
- LED 게이지는 충전 중엔 지금 파워, 아닐 땐 차례인 플레이어의 마지막 파워를 보여줘요.
- 난수는 16비트 LFSR (매 클럭 돌아감). 시뮬레이터는 8비트였어요.
- 결과 화면에서 피해 숫자(-35, +15)가 결과 문구(BACKFIRE 등)와 겹치는 칸은 문구를 보여줘요. 시뮬레이터는 숫자가 문구를 덮어서 "-15KFIRE"처럼 보였어요. 유성 화면에서는 숫자가 이겨요.
- 두 발 포탄: 첫 발로 누가 쓰러지면 둘째 발은 쏘지 않아요.
- LCD 한 글자 쓰기 대기는 100 us(여유 있게), 화면 전체 갱신은 약 10 ms예요.
